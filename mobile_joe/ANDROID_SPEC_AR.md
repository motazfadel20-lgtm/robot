ملف مواصفات وتخطيط هندسي — نسخة Android

1) نظرة عامة
- هدف المشروع: بناء تطبيق Android (مبني على `mobile_joe`) يوفّر لوحة تحكّم وتحليل بيانات مدعوم بالذكاء الاصطناعي، يدعم رفع صور وملفات، استيراد Excel/PDF، تسجيل ومراقبة المكالمات، وميزات إدارة صلاحيات (أدمن، مسوقين).
- أولوية: تجربة الموبايل أولاً (Android native - Kotlin).

2) ميزات أساسية (مُرتَّبة حسب الأولوية)
- واجهة رئيسية تعرض مربعات تفاعلية: عند النقر على أي مربع تظهر قائمة (List) تمثل العناصر المرتبطة.
- تسجيل دخول/صلاحيات: `Admin` بصلاحيات كاملة، `Marketer` بصلاحيات محدودة.
- رفع صور عبر الكاميرا وتحليلها عبر خدمة AI.
- رفع ملفات (PDF, DOCX, XLSX) ومعالجتها لاستخراج بيانات.
- استيراد Excel/PDF لملء جداول وإجراء تحليلات.
- تسجيل مكالمات (حيث يسمح النظام) أو رفع تسجيلات، ثم استخراج النتائج (نص/ملاحظات/تحليلات).
- تحويل النص إلى صوت والعكس (TTS/STT) للمكالمات والردود.
- إعادة طلب التوضيح عند وجود تشويش في الكلام.
- ميزة mute/listing: عند كتم يحجز النص محلياً، وعند محاولة اتصال آخر يبين موقع/إشعار (location).
- جمع الموقع الجغرافي وتحليل النقطة وإرجاع نتائج مرتبطة.
- جدول للصيدليات والأسعار مع واجهة إدارة.
- دردشة داخلية تربط بين نمطين وصلاحيات داتا مختلفة.

3) اقتراح بنية النظام
- تطبيق Android (Kotlin, Jetpack Compose أو XML UI اعتماداً على المشروع الحالي).
- Backend API: استخدم `api/` الموجود (PHP) أو أضف microservice (Python/Flask/FastAPI) لمعالجة AI وتحليل الملفات إن لزم.
- AI Layer: خياران
  - خدمة سحابية (OpenAI/Azure) لحلول STT/TTS/NLP وCharts.
  - محلي: Ollama (مذكور في repo) أو نموذج على السيرفر إذا مطلوب عدم الاعتماد على السحابة.
- Storage: ملفات وصور في S3 أو تخزين خادم (مع تخزين مسارات في DB).
- Database: MySQL/Postgres موجودة أو جديدة لتخزين المستخدمين، الصلاحيات، سجلات التحليل، جدول الصيدليات.

4) واجهات API مقترحة
- POST /api/v1/auth/login -> JWT
- GET /api/v1/dashboard/stats -> إحصائيات للتقارير
- POST /api/v1/upload/image -> رفع صورة + تحليل AI
- POST /api/v1/upload/file -> رفع PDF/XLSX + معالجة
- POST /api/v1/import/excel -> استيراد Excel
- POST /api/v1/audio/upload -> رفع/تحليل تسجيل صوتي
- POST /api/v1/ai/analyze -> تحليل عام (text/image/structured)
- GET /api/v1/pharmacies -> قائمة وأسعار

5) متطلبات Android وملفات/مكتبات مقترحة
- أذونات: CAMERA, RECORD_AUDIO, READ_EXTERNAL_STORAGE/WRITE_EXTERNAL_STORAGE, ACCESS_FINE_LOCATION.
- مكتبات: Retrofit + OkHttp, Room أو Realm، Jetpack Compose، WorkManager، ExoPlayer (تشغيل صوت)، ML Kit/Google Speech أو واجهات STT سحابية، Coroutine + Flow.

6) معالجة الملفات وExcel/PDF
- على السيرفر: استخدام مكتبات PHP/Python (PhpSpreadsheet, pandas, PyPDF2) لاستخراج الجداول ونقلها للـ DB.
- تحويل Excel إلى JSON ثم إرسالها إلى endpoint التحليل.

7) تحليل المكالمات وخصوصية
- عند توفر تسجيل: تحويل لصيغة نصية (STT) ثم تطبيق NLP لاستخراج الملخص، المشاعر، الكيانات.
- تأكّد من حفظ التسجيلات وفق سياسات الخصوصية وطلب موافقات المستخدم.

8) UX تفاصيل صغيرة
- عند الضغط على مربع: فتح BottomSheet أو شاشة جديدة تحتوي List بالعناصر (قابلة للفلترة والبحث).
- شاشة رفع صورة: معاينة، إمكانية إضافة ملاحظات، ثم إرسال لتحليل.
- شاشة إدارة الصلاحيات: قائمة المستخدمين، تغيير أدوار، تقييد وصول البيانات.

9) خطة تنفيذ مقترحة (مراحل قصيرة)
- مرحلة 1 (2 أسابيع): مصادقة + واجهة مربعات + قائمة عند النقر + رفع صور أساسي.
- مرحلة 2 (2-3 أسابيع): رفع ملفات PDF/XLSX + استيراد بيانات + جدول صيدليات.
- مرحلة 3 (2-3 أسابيع): تكامل AI (تحليل صور/نص)، STT/TTS، إعادة طلب عند تشويش.
- مرحلة 4 (2 أسابيع): تسجيل/رفع المكالمات وتحليلها، تحسينات أمان وصلاحيات.

10) مخاطر وبدائل
- تحميل النماذج محلياً يحتاج موارد عالية — الأفضل بدايةً API سحابي.
- تنوع صيغ PDF/XLSX قد يتطلب تنظيف بيانات متكرر.
